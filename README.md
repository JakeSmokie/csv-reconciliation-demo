# Сверка CSV-выгрузок

[Открыть страницу сверки](https://jakesmokie.github.io/csv-reconciliation-demo/)

Выберите готовый пример или загрузите две CSV-выгрузки. Получите суммы, список расхождений и отчёт, в котором каждую цифру можно проверить по исходной строке.

Сделал этот инструмент, чтобы сверять операции и выплаты по понятным правилам. Готовые примеры используют искусственные данные; можно проверить и собственные файлы того же формата.

## Попробовать в браузере

1. Откройте страницу и выберите пример. Расчёт появится автоматически.
2. Для своих данных раскройте **«Сверить свои CSV»**, выберите файл ожидаемых операций и файл выплат, затем нажмите **«Сверить файлы»**.
3. Если есть расхождения, сначала показаны **«Только проблемы»**. Кнопка **«Все строки»** открывает полный список; если всё совпало, он показан сразу. Откройте **«Исходные строки»** и скачайте текущий отчёт в **JSON или CSV**. Скачивание содержит весь отчёт независимо от фильтра; исходные файлы текущей сверки тоже доступны для скачивания.

Файлы обрабатываются в браузере и не отправляются на сервер. Установка Python, API-ключи и регистрация для браузерной сверки не нужны.

В шапке можно выбрать мягкую светлую, тёмную или системную тему. По умолчанию оформление следует настройке устройства; выбранный режим сохраняется локально в браузере. Этот выбор не связан с данными CSV.

| Готовый пример | Что можно проверить |
|---|---|
| Операции и выплаты | 14 итоговых ID: ожидается 5 215,00 ₽, выплаты 5 135,00 ₽, разница −80,00 ₽. Отклонения вниз 170,00 ₽ и вверх 90,00 ₽ показаны раздельно |
| Возврат и корректировка | 6 итоговых ID, обе суммы 108,60 ₽. Общий итог равен нулю, но две строки расходятся на копейку и ещё одна запись отсутствует |
| Повторный ID | Сверка останавливается с указанием дубля; прежние результаты скрываются, чтобы не принять их за отчёт по неверным данным |

Нулевое отклонение не отменяет отсутствие строки. Повторные ID не удаляются и не объединяются автоматически: для нескольких выплат на одну операцию требуется отдельное правило.

## Формат и точность

Оба файла — UTF-8 CSV с запятой. Формат показан на странице; [полный контракт](docs/contract.md) описывает заголовки, суммы, ID и обработку ошибок.

Браузерная версия читает CSV через локально сохранённый PapaParse 5.7.0 и рассчитывает деньги в целых копейках через `BigInt`. Денежный расчёт не использует `float`. В отчёте сохраняются исходные значения, физические номера строк и SHA-256 входных байтов.

Пределы браузерной версии: **5 МиБ и 100 000 записей на каждый файл**. Данные читаются в память. Это ограничения приёма данных, а не обещание скорости на любом устройстве. Для проверки SHA-256 нужен современный браузер и безопасный контекст HTTPS.

## Python-пример для локального запуска

В репозитории также сохранён небольшой отдельный пример из четырёх ID. **Это другой набор данных, а не начальный пример браузерной страницы:** ожидается 1 500,00 ₽, выплаты 1 405,00 ₽, разница −95,00 ₽; отклонения вниз 170,00 ₽ и вверх 75,00 ₽.

![Результат отдельного четырёхстрочного Python-примера](docs/demo.svg)

Скачать его [готовый отчёт](docs/report.json) и [операции](examples/expected.csv) / [выплаты](examples/actual.csv). Для запуска нужен Python 3.10 или новее, без внешних пакетов. Команды выполняются из папки репозитория:

```bash
python reconcile.py examples/expected.csv examples/actual.csv --out-dir generated
python -m unittest -v test_reconcile
```

Первая команда создаёт `generated/report.json` и `generated/report.csv`. Успех — код `0`, некорректные входные данные — код `2`. Повторный запуск заменяет отчёты в выбранной папке. Python-версия использует `Decimal`, принимает до 100 000 записей на файл и не имеет отдельного ограничения 5 МиБ. Она сохраняет абсолютные пути входных файлов в отчёте; в опубликованном примере они заменены относительными.

## Проверки

| Что важно | Как проверяется |
|---|---|
| Копейки не теряются | `BigInt` в браузере, `Decimal` в Python; случаи с десятичными дробями и корректировками |
| Ошибки не скрываются общим итогом | Раздельные отклонения вверх/вниз и проверка сохранения сумм |
| Соответствие строк не угадывается | Точные ID, отдельные статусы отсутствующей/неожиданной записи, отказ при дублях |
| Каждую цифру можно объяснить | Исходные значения, номера строк, SHA-256 и просмотр строки в интерфейсе |
| Текстовый ID не превращается в формулу CSV | Защитный апостроф в CSV для опасных начал ID; точный ID остаётся в JSON |
| Расчёт можно повторить | Готовые искусственные наборы, тесты браузерного движка и Python CLI |

Для тестов браузерного движка нужен Node:

```bash
node test_browser_engine.js
```

Автоматические проверки настроены в [GitHub Actions](.github/workflows/tests.yml). Статус конкретного коммита и результаты запусков смотрите во вкладке **Actions**.

## Для вашей задачи

Сверка рассчитана на подготовленные выгрузки одной валюты и согласованного периода. Здесь нет подключения к банку или маркетплейсу, расчёта налогов и определения бизнес-правил по догадке.

Для другого формата сначала посмотрю примеры, согласую ключ сопоставления, формулу, возвраты и вид отчёта. После этого смогу оценить объём, срок и стоимость. [Что нужно для оценки](docs/project-scope.md).

## Библиотеки

Интерфейс использует [mdui 2.1.5](https://github.com/zdhxiong/mdui), разбор CSV — [PapaParse 5.7.0](https://github.com/mholt/PapaParse). Обе библиотеки под лицензией MIT, сохранены локально с лицензиями, metadata и SHA в `docs/vendor/`. Для страницы не нужны внешние CDN или Google Fonts.
