# Как оценить инструмент

Автор проекта — Иван Айгузин, C#/.NET backend-разработчик. Этот небольшой пример на Python и JavaScript показывает подход к задачам сверки данных и автоматизации: входной контракт, точность, диагностику ошибок и проверку результата. Коммерческий опыт на .NET описан отдельно в резюме.

## Проверка за две минуты

1. Откройте [демонстрацию](https://jakesmokie.github.io/csv-reconciliation-demo/), выберите «Операции и выплаты» и найдите расхождение.
2. Посмотрите исходные строки: сумма в отчёте должна объясняться входными значениями, а не только итоговым статусом.
3. Выберите пример с повторным ID. Он должен отклоняться, а прежний результат — перестать выглядеть актуальным.
4. Скачайте JSON или CSV и сопоставьте отчёт с отображением на странице.

Примеры искусственные. Браузерная версия выполняет расчёт на устройстве пользователя; отдельный Python CLI воспроизводит тот же контракт.

## О чём поговорить на интервью

- Почему денежные расчёты используют `Decimal`/`BigInt` и где проходит граница округления?
- Почему повторные ID отклоняются вместо автоматического объединения?
- Как объясняется расхождение до физической строки исходного файла?
- Как проверяется соответствие Python- и JavaScript-реализаций?
- Как изменить контракт для частичных выплат, нескольких валют или больших файлов?

Демо не включает загрузку из банков и маркетплейсов, бухгалтерский учёт или многопользовательский сервис. Добавление таких возможностей потребует отдельного контракта, согласованных примеров и тестов.
