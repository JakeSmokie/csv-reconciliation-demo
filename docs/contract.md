# Контракт сверки

## Точная схема

Оба CSV: UTF-8 (BOM разрешён), разделитель запятая, первая строка — **точные headers в указанном порядке**, обычное CSV quoting. UTF-8 CSV с заголовком и без записей разрешён. Дополнительные колонки, недостающие ячейки и пустые строки отклоняются.

Ожидаемые операции:

```csv
id,gross,commission,refund
T001,1000.00,100.00,0.00
```

Фактические выплаты:

```csv
id,actual_net
T001,900.00
```

`expected_net` вычисляется как `gross - commission - refund`, его нет во входных колонках. Валюта этого контракта — RUB; все денежные колонки должны быть в одинаковых единицах. Значение — десятичное число с точкой и максимум двумя знаками после неё, без пробелов, научной записи, `NaN` и бесконечности. Целые числа разрешены. Допускается знак для корректировок; это арифметическое соглашение, а не проверка экономической корректности возврата.

ID — любая непустая строка; сопоставление точное, с учётом регистра, всех пробелов и управляющих символов. Никакого trim или нормализации ID нет. Дубли ID внутри любого из файлов отклоняются с номером первой и повторной строк. Автоматического агрегирования и сопоставления по приблизительному тексту нет. Если реальный экспорт содержит несколько выплат на операцию, нужен отдельный согласованный этап подготовки данных и правило агрегирования.

Ограничения: до 100 000 записей на файл; абсолютная сумма в одной денежной ячейке до `999999999999999.99`. Файлы загружаются в память. При этих границах 40 знаков Decimal достаточно для точной арифметики без float и округления копеек.

## Статусы, суммы и исходные строки

- `matched`: операция присутствует с обеих сторон, суммы равны точно.
- `mismatch`: операция присутствует с обеих сторон, суммы различаются.
- `missing`: ожидание присутствует, выплаты с этим ID нет.
- `unexpected`: выплата присутствует, ожидания с этим ID нет.

Для отсутствующей стороны арифметическое значение равно нулю; отсутствие отдельно отражено статусом и `null` source. Даже пропущенное ожидание с нулевой суммой остаётся `missing`.

`delta = actual_net - expected_net`; отрицательное значение — отклонение вниз, положительное — вверх. `underpayment` — сумма абсолютных отрицательных отклонений, `overpayment` — сумма положительных. Эти названия обозначают математические отклонения от переданного ожидания; они не являются выводом о неправомерных удержаниях.

Проверяются равенства:

```text
expected_total = gross_total - commission_total - refund_total
actual_total - expected_total = sum(each row delta)
actual_total - expected_total = overpayment - underpayment
```

JSON сохраняет SHA-256 прочитанных байтов каждого входа, его абсолютный путь, номера начальной/конечной физических строк каждой записи и исходные значения ячеек. CSV содержит те же суммы, номера строк и JSON исходных значений. Это восстановимые значения CSV-записи, а не буквальная копия кавычек/переносов исходного файла. Для ID, начинающихся с `=`, `+`, `-`, `@`, пробельного, управляющего (Unicode Cc) или форматирующего (Unicode Cf) символа, CSV добавляет защитный апостроф для текстового просмотра в таблице. JSON identity и ID в source values сохраняются точно; обычные безопасные ID экспортируются без изменения. Проверка охватывает также табуляцию, CR/LF, пробел перед формулой, control byte и BOM перед формулой.

В синтетическом примере ожидается 1 500.00 ₽, фактически 1 405.00 ₽, разница −95.00 ₽. Отклонения вниз 170.00 ₽ и вверх 75.00 ₽ показаны отдельно, поэтому нет сокрытия разнонаправленных ошибок одним итогом. Каждый из четырёх статусов встречается один раз.

## Браузерная сверка

Предыдущие разделы описывают исходный Python CLI и его четырёхстрочный искусственный пример. Браузерная версия использует тот же арифметический контракт и схему отчёта, но другой начальный набор данных и следующие особенности реализации.

### Входы и границы

- Два UTF-8 CSV, BOM разрешён; некорректная кодировка отклоняется.
- Разделитель — запятая. Заголовки и их порядок те же: `id,gross,commission,refund` и `id,actual_net`.
- Обычное CSV quoting поддерживается локально сохранённым PapaParse 5.7.0. Дополнительные/недостающие ячейки, неверные заголовки и пустые записи отклоняются; допустим завершающий перевод строки.
- До **5 МиБ входных байтов и 100 000 записей на каждый файл**. Это ограничения приёма, а не подтверждённая скорость обработки. Данные загружаются в память. Отдельный предел 5 МиБ относится только к браузерной версии.
- Денежные ячейки имеют прежний предел `999999999999999.99`, точку и максимум два десятичных знака. ID сравниваются точно, без trim и нормализации.
- Дубликат внутри любого файла останавливает расчёт с указанием исходных строк. Старый результат скрывается; неоднозначные данные не превращаются в частичный отчёт.

### Расчёт и результат

Денежные значения преобразуются в целые копейки `BigInt`, без арифметики `float`. Ожидание равно `gross - commission - refund`, отклонение равно `actual - expected`. Проверяются те же три равенства сохранения сумм. Разнонаправленные отклонения не схлопываются в одну категорию; отсутствующая нулевая запись остаётся `missing`.

Все операции выполняются в браузере. Выбранные файлы не отправляются на сервер. SHA-256 вычисляется по исходным байтам через Web Crypto; нужен безопасный контекст HTTPS. В полях `path` браузерный отчёт сохраняет имена файлов, без абсолютного пути компьютера. Исходные значения ячеек и физические номера строк сохраняются; CSV использует защитный апостроф для потенциально формульных ID, JSON — точный ID.

Фильтры, просмотр исходных строк и скачивание JSON/CSV относятся к текущему результату. Ссылки входных CSV также указывают текущие данные, а не всегда опубликованный четырёхстрочный набор. Это важно при сравнении с файлами из `examples/`: они относятся к отдельному Python-примеру.

### Искусственные контрольные примеры

| Пример | Контрольный результат |
|---|---|
| Операции и выплаты | 14 ID в объединении: 8 совпадений, 2 расхождения, 2 отсутствующие и 2 неожиданные записи. Ожидается 5 215.00 ₽, выплаты 5 135.00 ₽, разница −80.00 ₽, отклонения вниз 170.00 ₽ / вверх 90.00 ₽ |
| Возврат и корректировка | 6 ID, ожидание и выплаты 108.60 ₽. 3 совпадения, 2 расхождения и 1 отсутствующая нулевая запись. Общая разница 0.00 ₽, отдельно вниз 0.01 ₽ и вверх 0.01 ₽ |
| Повторный ID | D002 повторяется в выплатах, физические строки 3 и 4; обработка останавливается без нового отчёта |

Это тестовые суммы, а не реальная выручка или найденные клиентские удержания. Отрицательные суммы в примере возвратов — разрешённые арифметические корректировки; экономическую правильность такого правила определяет конкретная задача.

Библиотеки интерфейса mdui 2.1.5 и разбора CSV PapaParse 5.7.0 распространяются по MIT. Их локальные копии, лицензии и metadata находятся в `vendor/`. Публичность репозитория сама по себе не подтверждает успешную публикацию конкретной версии страницы: состояние развёртывания проверяется отдельно.

## Темы страницы

Оформление имеет светлый, тёмный и системный режим. По умолчанию используется настройка устройства; ручной выбор применяется без перезагрузки и не меняет текущую сверку. Выбранный режим сохраняется локально как настройка оформления. Если браузер запрещает такое сохранение, переключение работает до закрытия страницы без обещания сохранения на следующий визит.

Контроллер темы не сохраняет CSV или отчёты и не участвует в денежном расчёте. Обе палитры используют те же таблицу, статусы, фильтры и загрузки. Полупрозрачность ограничена шапкой; при предпочтении уменьшенной прозрачности она становится непрозрачной. Цветовая тема не добавляет никаких подключений к внешним сервисам.
